# 07. iOS 版のリリース手順（App Store）

基本情報ドリルの iOS 版（Capacitor 8）を App Store に公開するまでの手順。上から順に進める。

- Bundle ID：`com.kohki.m1106`
- アプリ名：基本情報ドリル
- 掲載文・回答の内容：`docs/app-store-listing.md`
- プライバシーポリシー：`public/privacy.html`（公開 URL `https://kohkim1106-a11y.github.io/fe-drill/privacy.html`）
- サポート：`public/support.html`（公開 URL `https://kohkim1106-a11y.github.io/fe-drill/support.html`）

**【本人のみ】** と書いた手順は、支払い、Apple ID でのサインイン、規約への同意を含むため、開発者本人が操作する。

---

## 0. 事前確認

- `public/privacy.html` と `public/support.html` を含む Web 版が GitHub Pages にデプロイされ、上の 2 つの URL がブラウザで開けること。App Store Connect の入力時と審査時に必要。
- Mac に最新の Xcode がインストールされていること（App Store からインストール）。
- 手元の iPhone（TestFlight での確認用）。

## 1. Apple Developer Program に個人で登録する 【本人のみ】

1. Apple Account（Apple ID）で **2 ファクタ認証** を有効にしておく（iPhone の「設定」→ 自分の名前 →「サインインとセキュリティ」）。
2. iPhone か Mac の「Apple Developer」アプリ、または <https://developer.apple.com/programs/enroll/> から登録を始める。
3. 登録の種類は **個人（Individual / Sole Proprietor）** を選ぶ。氏名は本名をローマ字で入力する。App Store の「販売元」にはこの氏名が表示される。
4. 個人の場合、**D-U-N-S 番号は不要**（D-U-N-S 番号が必要なのは組織として登録する場合）。
5. 年会費を支払う。金額は **年額 99 米ドル（日本では税込 12,980 円程度）**。金額は変わることがあるので、支払い画面に表示された金額を確認する。
6. 登録の承認には **最大 48 時間程度** かかることがある。承認されると「Apple Developer Program へようこそ」というメールが届く。
7. 承認後、<https://developer.apple.com/account> と App Store Connect（<https://appstoreconnect.apple.com>）にサインインし、表示される **プログラム使用許諾契約** に同意する。無料アプリだけを配布する場合、有料アプリ契約（銀行口座・税務情報）の登録は不要。

## 2. Xcode の署名を設定する

1. **【本人のみ】** Xcode を開き、メニューの **Xcode › Settings… › Accounts** で左下の「+」→「Apple Account」を選び、登録した Apple ID でサインインする。チーム名（個人の場合は自分の氏名）が表示されることを確認する。
2. ターミナルでリポジトリのフォルダに移動し、次を実行する。Web 部分をビルドして iOS プロジェクトに反映し、Xcode でプロジェクトが開く。

   ```sh
   npm run ios
   ```

   （開かない場合は Xcode で `ios/App/App.xcworkspace`、なければ `ios/App/App.xcodeproj` を直接開く。）
3. 左のナビゲータで一番上の「App」プロジェクト → TARGETS の「App」→ **Signing & Capabilities** タブを開く。
   - **Automatically manage signing**：オン
   - **Team**：自分のチーム（氏名）を選ぶ
   - **Bundle Identifier**：`com.kohki.m1106` になっていることを確認する
4. エラーが出なければ、Xcode が証明書と Provisioning Profile を自動で作る。「Failed to register bundle identifier」と出る場合は、その Bundle ID が別のアカウントで使われている。その場合は Bundle ID を変える必要があるので、`capacitor.config.ts` の `appId` とあわせて変更する。
5. **General** タブで **Version** が `1.0`、**Build** が `1` になっていることを確認する。

## 3. App Store Connect でアプリを作成する 【本人のみ】

1. <https://appstoreconnect.apple.com> にサインインし、「アプリ」→ 左上の「+」→「新規 App」。
2. 次のように入力する。
   - プラットフォーム：**iOS**
   - 名前：**基本情報ドリル**（App Store 上で他のアプリと重複している場合は使えない。その場合は「基本情報ドリル - FE対策」など、30 文字以内で区別できる名前にする）
   - プライマリ言語：**日本語**
   - バンドル ID：一覧から **com.kohki.m1106** を選ぶ（手順 2 で Xcode が登録していれば表示される。表示されない場合は <https://developer.apple.com/account/resources/identifiers> で同じ ID を登録する）
   - SKU：社内管理用の任意の文字列。例：`fe-drill-ios`
   - ユーザーアクセス：**フルアクセス**
3. 「作成」を押す。

## 4. 掲載情報を入力する

`docs/app-store-listing.md` の内容をそのまま入力する。

1. **App 情報**（左メニュー「一般」→「App 情報」）
   - サブタイトル、カテゴリ（プライマリ：教育、セカンダリ：辞書/参考書）
   - 年齢制限：「設定」から質問票に回答する（すべて「なし／いいえ」→ 4+）
   - コンテンツの権利：「第三者のコンテンツを含む」かを聞かれたら **はい** を選ぶ（IPA の公開問題を含むため）。IPA の FAQ により、出典を明記すれば許諾申請なしで利用できることを確認している（`docs/06-ipa-sources.md`）。
2. **App のプライバシー**（左メニュー「App のプライバシー」）
   - プライバシーポリシー URL：`https://kohkim1106-a11y.github.io/fe-drill/privacy.html`
   - 「データの収集について」→「**いいえ、このアプリではデータを収集しません**」→ 公開する
3. **価格および配信状況**
   - 価格：**無料**（0 円）
   - 配信状況：配信する国・地域を選ぶ。日本語のアプリなので **日本のみ** でもよいし、すべての国・地域でもよい。
4. **バージョン 1.0 の情報**（左メニュー「iOS App」→「1.0 提出準備中」）
   - プロモーションテキスト、説明文、キーワード、サポート URL、マーケティング URL、著作権
   - スクリーンショットは手順 7 で撮ってからアップロードする
   - App Review に関する情報：「サインインが必要」のチェックを外し、メモ欄に `docs/app-store-listing.md` の「App Review への備考」を貼る。連絡先（氏名・電話番号・メールアドレス）は審査担当者だけに見える欄で、入力が必要。 **【本人のみ】**
   - バージョンのリリース：「手動でリリース」にしておくと、承認後に自分のタイミングで公開できる

## 5. ビルドしてアップロードする

1. ターミナルで最新の Web 部分をビルドし、iOS プロジェクトに反映する。

   ```sh
   npm run build:ios
   ```

2. Xcode の上部の実行先（デバイス選択）で **Any iOS Device (arm64)** を選ぶ。シミュレータを選んでいると Archive できない。
3. メニューの **Product › Archive** を実行する。完了すると Organizer ウインドウが開く。
4. 作成したアーカイブを選び、**Distribute App** →「**App Store Connect**」→「Upload」（または「Distribute」）を選び、画面の指示どおり進める。署名は自動のままでよい。
5. アップロード後、App Store Connect の「TestFlight」タブにビルドが表示されるまで数分から数十分かかる。処理が終わると Apple からメールが届く。
6. 輸出コンプライアンス（暗号化）の質問は、`Info.plist` に `ITSAppUsesNonExemptEncryption = NO` を設定済みなので表示されない。表示された場合は「免除される暗号化のみ／使用していない」を選ぶ。

## 6. TestFlight で自分の iPhone で確認する

1. App Store Connect の「TestFlight」→「内部テスト」でグループを作り、自分（Apple ID）をテスターに追加して、アップロードしたビルドを割り当てる。内部テストは Apple の審査なしで使える。
2. iPhone に App Store から「TestFlight」アプリを入れ、届いた招待からインストールする。
3. 次の項目を確認する。

   - [ ] **機内モードで起動できる**：機内モードにしてからアプリを完全に終了し、起動する。ホーム、演習、カード、分析の各タブが表示され、問題を解ける。
   - [ ] **学習リマインダーが届く**：設定画面（「分析」タブから開く）の「学習リマインダー」で「毎日通知する」をオンにし、時刻を 1〜2 分後にする。通知を許可し、アプリを閉じて待つ。通知が届き、タップするとアプリが開く。
   - [ ] **通知を拒否した場合**：iPhone の「設定」→「通知」で本アプリをオフにすると、アプリ内に許可を促す案内が表示される。
   - [ ] **カードのスワイプ**：カードをタップで裏返し、左右のスワイプで「覚えた」「まだ」に仕分けられる。スクロールと誤動作しない。
   - [ ] **ダーク／ライト**：設定のテーマで「ダーク」「ライト」「システム」を切り替え、全画面で文字が読める。iPhone 本体の外観モードを切り替えたとき「システム」が追従する。
   - [ ] **模試の中断と再開**：模試を途中で中断し、アプリを完全に終了してから開き直すと、演習メニューの「中断中の模試を再開」から続きを解ける。
   - [ ] 記録が残る：問題を解いてからアプリを終了・再起動しても、分析の記録が残っている。
   - [ ] 画面の上下（ノッチ、ホームインジケータ）に表示が隠れない。
   - [ ] 問題画面の「誤りを報告」で問題 ID をコピーできる。

4. 問題があれば修正し、手順 9 の要領でビルド番号を上げて再アップロードする。

## 7. スクリーンショットを撮る

必要なのは **6.9 インチ（1320 × 2868 ピクセル、縦向き）** の画像。撮る画面とキャプションは `docs/app-store-listing.md` の「スクリーンショット」を参照（5 枚）。

1. Xcode の実行先で **iPhone 16 Pro Max**（または iPhone 17 Pro Max）のシミュレータを選び、実行（Product › Run）する。
2. 数日分の問題を解くなどして、ホームと分析に記録が表示される状態にする。テーマはダークに統一する。
3. 撮りたい画面を表示し、ターミナルで次を実行する。

   ```sh
   xcrun simctl io booted screenshot ~/Desktop/fe-drill-01-home.png
   ```

   ファイル名を変えながら 5 枚撮る。シミュレータのメニュー File › Save Screen（⌘S）でも保存できる。
4. 画像のサイズを確認する。

   ```sh
   sips -g pixelWidth -g pixelHeight ~/Desktop/fe-drill-01-home.png
   ```

   1320 × 2868 であれば、そのまま App Store Connect の「6.9 インチディスプレイ」にアップロードできる。キャプションを入れる場合は、同じサイズのまま画像編集ソフトで文字を重ねる。
5. ステータスバーの時刻などを整えたい場合は、撮影前に次を実行する。

   ```sh
   xcrun simctl status_bar booted override --time 9:41 --batteryLevel 100 --batteryState charged
   ```

## 8. 審査に提出する

1. 「1.0 提出準備中」の画面で「ビルド」欄の「+」から、手順 5 でアップロードしたビルドを選ぶ。
2. すべての必須項目が埋まったら、右上の「審査用に追加」→「審査に提出」。 **【本人のみ】**（提出前に表示される確認事項・規約への同意を含む）
3. 審査は通常 1〜2 日程度で結果が出る。結果は App Store Connect とメールで通知される。リジェクトされた場合は「App Review」の画面に理由が書かれるので、修正するか、返信欄で説明する。

### よくあるリジェクト理由と本アプリでの対応

| ガイドライン | 内容 | 本アプリの対応 |
|---|---|---|
| 4.2 最低限の機能 | Web サイトをそのまま包んだだけのアプリは却下されやすい | 全データを同梱し、通信なしで動作する。端末内で予約するローカル通知による学習リマインダー、正誤に応じて復習の間隔を変える出題、スワイプで仕分ける用語カード、中断・再開できる模試など、アプリとしての機能を備える。審査メモにも試し方を書く。 |
| 5.1.1 データの収集と保存 | プライバシーポリシーの欠如、不要なデータ収集、ログインの強制 | データを収集せず、ログインもない。プライバシーポリシーを公開し、App のプライバシーは「データの収集なし」で一致させる。通知の許可は、利用者が設定でリマインダーをオンにしたときにだけ求める。 |
| 2.1 App の完成度 | クラッシュ、リンク切れ、未完成の画面、審査で試せない機能 | 手順 6 のチェックリストで確認する。サポート URL とプライバシーポリシー URL が開けることを提出前に確認する。v1.0 では同期（ログイン）機能が表示されないことを確認する。 |
| 5.2 知的財産 | 第三者のコンテンツを権利なしに使用 | IPA の公開問題は IPA の FAQ に従い、出典と改変の旨を各問題に表示し、著作権が IPA にあることを明記している。審査メモに FAQ の URL を記載する。 |
| 2.3 正確なメタデータ | 説明文やスクリーンショットが実際のアプリと違う | 説明文は実装済みの機能だけを書いている。スクリーンショットは実際の画面を使う。 |

## 9. あとからアップデートする

1. コードを修正したら、次を実行して iOS プロジェクトに反映する。

   ```sh
   npm run build:ios
   ```

2. Xcode の TARGETS「App」→ **General** で番号を上げる。
   - **Version**（利用者に見える番号）：機能追加なら `1.1`、修正だけなら `1.0.1` など
   - **Build**：アップロードのたびに必ず増やす（`1` → `2`）。同じ Version で再アップロードする場合も Build は上げる。
3. 手順 5 と同じく Product › Archive → Distribute App でアップロードする。
4. App Store Connect で「+」から新しいバージョン（例：1.1）を作り、「このバージョンの新機能」を書いてビルドを選び、審査に提出する。 **【本人のみ】**
5. 将来、Firebase を使ったログイン同期を追加する場合は、**公開前に** `public/privacy.html` を改定し、App Store Connect の「App のプライバシー」の回答（収集するデータ、利用目的）も更新する。年齢制限やレビュー用のデモアカウントの要否も見直す。

## 本人だけが行う操作のまとめ

- Apple Account の 2 ファクタ認証の設定
- Apple Developer Program の登録と年会費の支払い
- Apple Developer / App Store Connect の契約・規約への同意
- Xcode への Apple ID のサインイン
- App Store Connect でのアプリ作成、審査用連絡先の入力
- 審査への提出（提出時の確認事項への同意を含む）
- 承認後の公開（「手動でリリース」にした場合）
