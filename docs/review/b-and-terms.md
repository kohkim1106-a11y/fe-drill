## 検証方法

- アルゴリズム問題（32問）は、すべて Python に書き直して実行した（`python3 -I`、作業用フォルダ内で実行し、リポジトリには置いていない）。添字は1始まりで、範囲外を参照すると例外になる配列クラスを使った。
  - 穴埋め問題：すべての選択肢を実装し、ランダムに作った入力（各数百〜3000件）で参照実装と比べた。正しく動く選択肢はどの問題でもちょうど1つだった。b-algo-020 だけは「終値 n、n − i + 1」も正しく判定するが、問題文の「比較回数が最も少ない」という条件で除外されるので、正解は1つに定まる。
  - トレース問題：戻り値、途中の状態、呼出し回数などを実行して求め、正解の選択肢と一致することを確かめた。
  - 解説に書かれている誤答の理由（反例、範囲外参照、無限ループなど）も実行して確かめた。
- セキュリティ問題（8問）は、正解の行動がほかの選択肢より明らかに適切かどうかを確かめた。
- 用語は、定義、公式、似た用語との違い、分類（minor）を確かめた。ID と用語名がファイルをまたいで重複していないことも、スクリプトで確かめた。

## 要検討事項（修正していない）

1. **term-v-model（V字モデル）**：工程とテストの対応を「要件定義↔システムテスト、外部設計↔結合テスト、内部設計↔単体テスト」としている。よく使われる対応だが、教材によっては「要件定義↔運用（受入れ）テスト、外部設計↔システムテスト」とするものもある。「対応のさせ方は資料によって異なる」と一言加えてもよい。
2. **term-preemptive（プリエンプション）**：「リアルタイムOSで使われる」と書かれているが、一般的な汎用OSでも使われる。限定的に読めるので、「多くのOSで使われ、特にリアルタイムOSで重要」とする案がある。
3. **term-data-mining**：例として挙げている「おむつとビール」は、事実かどうか疑わしい逸話として知られている。試験対策の例としては広く使われているので残した。
4. **term-naibu-tousei（内部統制）**：目的を「財務報告の信頼性」としている。2023年改訂の実施基準では「報告の信頼性」に広げられた。試験でよく出る表現としては今の書き方で問題ない。
5. **term-pmbok**：「知識エリア」は第6版までの構成で、第7版は原則とパフォーマンス領域が中心になっている。シラバスと過去問では知識エリアの形がよく出るので、修正の必要は低い。

## 個別の確認結果（要点）

- b-algo-001〜032：正解はすべて正しく、ほかの選択肢では正しく動かないこと（または正しい値にならないこと）を確認した。例：b-algo-005 の mid は 5, 8, 6、b-algo-012 は fib(5)=5 で呼出し9回、b-algo-024 は 108=1101100₂ で4、b-algo-025 は 10001101、b-algo-026 は添字1、b-algo-028 は 21 で3回、b-algo-030 は7回。b-algo-031（参照のコピー）は手でトレースして 12。
- b-sec-001〜008：初動対応（ネットワークから切り離す、記録を残す、報告する）、BEC 対策（別の経路で確認する）、パスワードスプレー攻撃の見分け方などは、IPA の一般的な指針と合っている。どの問題も、正解以外の選択肢は明らかに不適切。
- 用語300語：公式（稼働率、実効アクセス時間、CPI・MIPS、損益分岐点、EVM、コミュニケーション経路数、共通鍵の数、サブネットのホスト数など）はすべて正しい。用語名と ID に重複はない。内容が似ている組（リスクアセスメント／リスク対応、プラスのリスク）も、扱っている観点が違うので重複とはみなさなかった。

## 総合評価

全体として品質は高い。アルゴリズム問題は、擬似言語の約束（1始まりの添字、and の短絡評価の明記、mod など）に忠実で、誤答の選択肢も典型的なミス（境界の ±1、比較の向き、範囲外参照）を狙ってよく作られている。解説もほぼ正確だった。正解の誤りは1件もなく、修正は解説1件と用語2件の表現・定義の精度にとどまる。セキュリティ問題は場面設定が具体的で、正解は明確。用語は試験範囲を広く押さえていて、似た用語との違いもうまく盛り込まれている。
