## 3. 並列化の考え方

- 設計（5.3）でファイルの持ち場と型定義（`src/types`）を先に固定し、エージェント同士が同じファイルを触らないようにする
- 問題データ担当（C〜F）は、共通の JSON スキーマに従って別ファイルに出力する
- 統合とテストは並列製造の完了後に私がまとめて行う

## 4. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| AIが作った問題・解説に誤りがある | 誤って覚える | 検証スクリプト＋別エージェントによる内容レビュー。誤り報告ボタンを付ける |
| IPAのPDFから図表付き問題を正確にデータ化できない | 収録数が減る | 図表なしで成立する問題を優先。図が必要な問題は対象外にする |
| Firebase 未設定のまま使う | 同期できない | ローカルだけで全機能が動く設計にする |
| GitHub にログインできていない | 公開が止まる | デプロイ前に `gh auth login` をお願いする |
